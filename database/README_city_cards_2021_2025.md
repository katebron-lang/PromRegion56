# Заполненные карточки городов 2021–2025

Города: Новотроицк (city_id=1), Орск (city_id=2), Оренбург (city_id=3).

## Что внесено

- В `database/industrial_city_db.sql`: 15 годовых записей `territory_metrics` (5 лет × 3 города), 3 источника, реквизиты городов.
- В `database/city_annual_indicators.sql`: 140 детальных строк, единицы измерения, статус `reported` / `municipal_estimate` / `unavailable`, даты наблюдения и примечания по сопоставимости.
- В `city-cards.html`: статическая витрина тех же опубликованных значений. **Карточки пока не считывают изменения базы автоматически.**

## Установка в PostgreSQL

**Для работающей PostgreSQL-базы:** после резервной копии применяйте только `database/migrate_city_cards_existing_db.sql`. Скрипт добавляет отсутствующие источники и годовые записи, заполняет NULL в `territory_metrics`, не перезаписывает существующие значения, создаёт подробную таблицу и добавляет отсутствующие строки. Повторное выполнение допустимо. При этом скрипт не предназначен для базы с иной схемой или несоответствующей нумерацией городов; перед применением проверьте, что города 1–3 — Новотроицк, Орск и Оренбург.

Для **новой пустой** базы сначала восстановите полный дамп, затем выполните отдельный файл подробных показателей.

Применение в уже работающей БД (только после резервного копирования):

```bash
psql -v ON_ERROR_STOP=1 "$DATABASE_URL" -f database/migrate_city_cards_existing_db.sql
```

Для совершенно новой пустой БД:

```bash
psql -v ON_ERROR_STOP=1 -d industrial_city_db -f database/industrial_city_db.sql
psql -v ON_ERROR_STOP=1 -d industrial_city_db -f database/city_annual_indicators.sql
```

Проверка (ожидается 5 строк по каждому городу в `territory_metrics` и 140 строк в подробной таблице):

```sql
SELECT city_id, count(*) AS annual_rows FROM territory_metrics
WHERE city_id IN (1,2,3) GROUP BY city_id ORDER BY city_id;
SELECT city_id, count(*) AS indicator_rows,
       count(*) FILTER (WHERE numeric_value IS NULL) AS unavailable_values
FROM city_annual_indicators GROUP BY city_id ORDER BY city_id;
```

## Ограничения, которые нельзя скрывать

1. У Новотроицка в отчёте за 2025 год нет подтверждённой годовой зарплаты. Численность 78 871 относится к 01.01.2025, а не к концу 2025 года. В основной таблице за 2025 год поля оставлены NULL; в подробной сохранён исходный снимок с датой.
2. В Оренбурге не подтверждены сопоставимые значения за 2021 год по отгрузке, инвестициям, безработице, населению и прибыли. `NULL` — отсутствие подтверждённых данных, не нулевая величина.
3. У Орска розничная торговля после 2022 года учитывается по иному охвату организаций. Перепад населения между 2022 и 2023 годами не следует без дополнительной проверки считать обычной убылью.
4. `industrial_output` в `territory_metrics` заполнен по показателю отгрузки в действующих ценах (рубли), не по индексу промышленного производства; он не эквивалентен выручке юридических лиц. В подробной таблице исходное название показателя сохранено.
5. `oktmo` в `cities` — 11-значный код населённого пункта; для сравнения по муниципальным образованиям используйте муниципальные 8-значные коды: Новотроицк 53720000, Орск 53723000, Оренбург 53701000.

Источники: муниципальные отчёты по Новотроицку и Орску, отчётные постановления по Оренбургу, официальные классификаторы ОКТМО. В основном дампе ссылки/описания хранятся в `data_sources` (ID 362–364). По Орску документы переданы для проекта; веб-ссылка в БД не придумана.
